## Charter check: keyword matching

Asked for on the call, because it decides how keywords are reported.

- **The charter does not say all-or-nothing.** Its setup wireframe has a *Match Logic*
  toggle — “ANY keyword matches” / “ALL must match” — and says to **default to ANY**.
- Match logic was dropped from setup on 1 Oct, so which one the backend does is
  currently unstated.
- The charter's **reporting guardrail** keeps per-keyword breakdowns to CSV and the API
  at launch, with no per-keyword charting in the dashboard.

Full performance is built on Product's reading — keywords as one set, which is one row
per campaign and stays inside the guardrail. Needs an answer before build.

## Campaign Health maths is a placeholder

Product is settling the rule with engineering, and said it can run in the front end.
Until then the prototype uses: **green** when spend is within 10% of the share of the
flight that has gone (ahead counts as green); **orange** when it's behind but the daily
spend needed to finish is at most 1.5× today's; **red** beyond that. Only live campaigns
with a budget have a health. It is written down once, in
`prototypes/das/v4/screens/campaign-data.ts`, so it can be replaced in one place.

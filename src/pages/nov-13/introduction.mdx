## How this category is organised

The order follows the call: a category, then each component or page, then a story for
every state it has (empty, error, no permission, each chart type), and documentation
alongside.

- **Introduction, Direction, Engineering constraints, Screen index** — what this is, what
  was agreed on 13 November, what can't be restyled, and every screen in one list.
- **Reporting · Demand · Deal Activation System · AdOps · SDK & Docs · Finance ·
  Settings** — the dashboard's own sidebar, one folder per page, one story per state.

## The style guide, in short

- **Type:** headlines 800, labels 700, nothing under 15px.
- **Tables:** reports get the charcoal header, lists a light one; both run full bleed with
  rules between columns, and every column sorts.
- **Reporting pages** share one shape: the date row, bands of metric and breakdown
  checkboxes, filters, the chart type bar, then the chart and its report table.
- **Fields, dropdowns, checkboxes and toggles** take staging's look with a teal focus.
- **Copy** keeps staging's wording; pages state the data and never coach.
- **Sample data** is fictional throughout: this Storybook is public.

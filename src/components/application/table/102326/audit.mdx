# App Screens table audit · 102326

Audited **23 October 2026**: **17 App Screens areas, 59 story states, 20 table implementations** (15 shared React Aria tables and 5 custom HTML tables). **30 story states contain semantic tables.** The benchmark leaderboard adds two ranked definition lists, included as a table-like example.

This folder extracts the examples already used by the local App Screens category. The original screens and these examples share their table components and fixtures; table markup and styling are preserved. Page navigation is omitted so complete rows, columns, controls and states can be reviewed together. This is a UI inventory of the local design system, not an audit of the live publisher dashboard.

## Findings to resolve before standardizing

1. **Two table systems and multiple densities.** HTML billing, review, reporting and benchmark tables bypass the shared sizing, focus and sorting behavior. Their styles are intentionally retained here for comparison.
2. **Sort icons often imply unavailable behavior.** Standard Ad Blocking and Manage Assets live campaigns actually sort rows. Other headers expose sort affordances without a data-sorting handler; the detailed blocklists, wide campaigns, billing, reporting, benchmarks and payout examples retain this limitation.
3. **Most actions are illustrative.** Enable toggles and editable fields change locally. Save, Delete, Add, Download, Duplicate, payment, copy and test controls generally have no persistence/action handler in these App Screens examples. This folder does not introduce new backend behavior.
4. **Financial fixtures need review.** Source totals and amounts are sample values; some totals do not reconcile with displayed rows. The monthly payment overview also repeats the label “Demand” and uses “Blocked By” in a payment table. These values/labels are preserved and visible in Payments → Monthly Overview.
5. **State coverage is uneven.** Payouts include unsubmitted, complete, billing and issue states, and campaign review includes an error variant. The table implementations do not offer a shared loading, empty, search-no-results, server-error or pagination state. The Performance Insights empty story is a chart/configuration state rather than a reusable table empty state.
6. **Accessibility needs a follow-up pass.** React Aria tables expose labels, row headers and keyboard table behavior; custom HTML tables vary in header scope and labeling. Several action columns are unlabeled. In the sampled live-campaign shared table, visible header labels are exposed as groups while the columnheader accessible names are empty. Preserve visual references here, then agree on a common accessible table contract before migration.

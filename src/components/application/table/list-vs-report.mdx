# Tables · List vs Report

Settled on the 26 Oct review, so it can be written down once and reused by the
Performance Insights redesign:

> “Reports have this charcoal table, and then the alternating tan … when it's data like
> this. And then when it's like a list of stuff, I think I drop it. It's not a report, it's
> just an organised list. I think that's loosely the rule.”
>
> — Product, 26 Oct review

- **Report** — numbers about delivery: **charcoal #101828 header, white labels, warm
  alternating rows**, a totals row where the numbers add up.
- **List** — an organised set of things you act on: **light header, bold black labels**.
- **Both** have **vertical rules between columns** and, on a page, run **full bleed** —
  edge to edge of the content area, like staging's tables — with the first and last cells
  lining up with the page padding. A table inside a form section (the selected-items
  tables in setup) stays inside its section.

One place to change it: `TABLE` and `tableHead` in
`prototypes/das/v5/screens/nimbus-ui.tsx`. The examples below are drawn with them.

## Staging today is inconsistent

Built by many hands over many years, staging doesn't follow one rule yet. These are the
known exceptions, to settle in the Performance Insights redesign rather than copy:

- **Manage Active Demand** has a **charcoal** header, though it's a list — the same shape
  as Manage Campaigns, which is light.
- **Nimbus+ Payments** and **Nimbus+ Payouts** have **light** headers, though they're
  reporting.
- **Saved Queries** (Performance Insights) is a list of saved reports with a charcoal header.

Product's guidance: follow the designs, not the implemented exceptions, and change the
rule in one place when it's settled.

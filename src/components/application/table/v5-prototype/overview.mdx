# V5 Prototype · tables and matching components

Round 5 applies the **26 Oct rule** (see <a href="./?path=/docs/application-ui-table-list-vs-report--docs" target="_top">List vs Report</a>):
**reports get the charcoal header; lists keep a light one.** Both have bold labels and
vertical column rules, and on a page they run full bleed, edge to edge of the content
area, the way staging's tables do.

This inventory maps the **seven table implementations** in prototype v5 to the closest
existing design-system examples. The v5 stories render the actual prototype components,
with the full screen around the table for context. Round 4 stays frozen at `das/v4` as it
was reviewed.

## Notes

- **Kind decides the header, nothing else.** A list is an organised set of things you
  act on (campaigns, assets, keywords, selected items). A report is numbers about
  delivery (Full performance, per keyword). Product, 26 Oct: “Reports get the charcoal
  headlines … when it's like a list of stuff, I think I drop it.”
- **These are native HTML tables styled from one place:** `TABLE` and `tableHead` in
  `prototypes/das/v5/screens/nimbus-ui.tsx`. Change the rule there and every v5 table
  follows. The selected-items pattern is one shared component across Apps, Device
  Language, Keywords and Creative, and stays inside its form section rather than bleeding.
- **Type floor.** V5 holds text to its 15px minimum, so header labels are larger than
  staging's 12–13px; colour, weight, rules and stripes follow staging.
